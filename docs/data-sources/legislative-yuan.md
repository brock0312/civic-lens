## 逐項詳細記錄

### 1. 委員名單與選區

**來源：`https://v2.ly.govapi.tw/legislators`**
- 實測：`curl "https://v2.ly.govapi.tw/legislators?屆=11&limit=2"` → **HTTP 200**，JSON
- 欄位（節錄）：`屆`、`委員姓名`、`委員英文姓名`、`性別`、`黨籍`、`黨團`、`選區名稱`、`委員會`（逐會期歷史）、`到職日`、`離職日期`、`離職原因`、`學歷`、`經歷`、`照片位址`、`歷屆立法委員編號`、`電話`、`傳真`、`通訊處`
- 支援 filter：`屆`、`黨籍`、`選區名稱`、`歷屆立法委員編號`、`委員姓名`
- 第11屆總筆數：123（含遞補與離職者，須用 `是否離職`/`離職日期`/`離職原因` 判斷現任狀態）
- 授權：CC BY 4.0（見 govapi 首頁 footer 連結 `creativecommons.org/licenses/by/4.0`）
- 更新頻率：文件未明示；`bills` 回應含 `資料抓取時間`（本次為 2026-09-28T09:26），顯示每日或更頻繁更新
- 速率限制／API key：實測未遇到限流或需金鑰，屬公開匿名存取
- 已知坑：
  - 同一姓名可能跨屆對應不同 `歷屆立法委員編號`，姓名比對需以此編號為準，勿只用姓名字串
  - 有名字含羅馬拼音/原住民族名併列（如「鄭天財Sra Kacaw」），前端顯示與比對邏輯需處理
  - 遞補委員以 `到職日`/`離職原因`（如「辭職」）標記，第11屆已見樣本（吳春城 2025-02-27 辭職）

### 2. 出席紀錄

**來源：`https://v2.ly.govapi.tw/meets`**
- 實測：`curl "https://v2.ly.govapi.tw/meets?委員會代號=3&limit=1"` → HTTP 200，但 `total:0`（該委員會代號查無資料，代號對照表未知）
- 一般查詢（無 filter）回傳筆數 8251，欄位含 `會議資料.出席委員`，但抽樣的公聽會紀錄該欄位為空陣列 `[]`
- **結論：端點存在且結構支援出席名單，但實測樣本出席資料常缺漏，完整度不明，需要更多抽樣或改用院會公報/議事錄比對**
- 已知坑：委員會代號的對照表本次未查到，需另外向 API 文件或 swagger 確認

### 3. 質詢紀錄

**來源：`https://v2.ly.govapi.tw/interpellations`**
- 實測：HTTP 200，JSON，總筆數 11691
- 欄位：`屆`、`質詢委員`（陣列，可能多人聯合質詢）、`會議代碼`、`會議代碼:str`（可讀會期會次）、`質詢編號`、`質詢起始頁`/`質詢結束頁`（對應公報頁碼）、`刊登日期`、`事由`、`說明`（質詢全文摘要）
- 這是**書面質詢**性質資料（有公報頁碼可回溯全文）；口頭質詢/總質詢逐字稿需另外核對是否同一端點涵蓋或需搭配 IVOD 逐字稿
- 授權同 govapi 整體 CC BY 4.0

### 4. IVOD 影片連結

**來源A：`https://v2.ly.govapi.tw/ivods`（已實測可用，結構化查詢）**
- 實測：HTTP 200，總筆數 104682
- 欄位：`IVOD_ID`、`IVOD_URL`（`ivod.ly.gov.tw/Play/Full/1M/{id}` 形式）、`video_url`（可直接播放的 m3u8 串流網址）、`委員名稱`、`會議時間`、`會議名稱`、`會議資料`（屆/會期/委員會代碼/種類）、`影片長度`、`委員發言時間`、`日期`、`開始時間`/`結束時間`、`影片種類`
- **可用委員姓名＋日期／屆會期查詢個別影片**：`filter` 支援欄位包含委員相關欄位（本次抽樣未逐一列出全部 supported_filter_fields，建議另測 `?委員名稱=XXX`）
- 已知坑：抽樣紀錄的「委員名稱」在黨團協商類會議中可能為 null（非個人質詢場次）

**來源B：官方 `ivod.ly.gov.tw` 網站**
- `curl` 直連失敗：**TLS handshake failure — `unsafe legacy renegotiation disabled`**（伺服器要求舊式 TLS renegotiation，現代 OpenSSL 用戶端預設拒絕）
- `WebFetch` 可讀取首頁（走不同的 HTTP 客戶端），確認網站結構為 `/Live`、`/Forecast`、`/Demand`、`/Map`、`/Faq`、`/News`、`/Statistics`，但未能在首頁看到公開 API 文件
- **結論：程式化存取應走 govapi 的 `video_url`／`IVOD_URL`，官網本身不建議做爬蟲直連（TLS 相容性差，且需模擬瀏覽器）**

### 5. 提案、表決、公報

## 缺口與風險

1. **出席紀錄完整度存疑**：`/meets` 的 `出席委員` 欄位在抽樣中常是空陣列，尚未確認是否有其他欄位或端點能穩定取得逐次會議簽到名單；需要更大樣本測試或改以「表決出席人數＋投票委員名單」間接推算出席（但表決僅涵蓋有表決的會議，非逐次簽到）。
2. **口頭質詢/總質詢逐字稿覆蓋範圍未確認**：`/interpellations` 樣本目前看起來偏向書面質詢（有公報頁碼），需另外確認總質詢口頭質詢是否也在此端點或需另尋公報全文比對。
3. **官方 `data.ly.gov.tw` 與 `ivod.ly.gov.tw` 的 TLS 相容性問題**：伺服器要求「unsafe legacy renegotiation」，現代 OpenSSL（含多數程式語言預設 HTTP 客戶端）會直接拒絕連線。若專案未來需要直連官方源（而非透過 govapi 轉手），需要用允許 legacy renegotiation 的客戶端設定（例如自訂 OpenSSL `SSL_OP_LEGACY_SERVER_CONNECT` 或改用瀏覽器渲染），這是實質的工程風險，不只是文件問題。
4. **govapi 為非官方社群維運**：資料來源可靠性依賴 OpenFun/g0v 社群長期維護，需記錄其資料來源聲明（是否自官方 data.ly.gov.tw 或 ivod 爬取轉存）、更新延遲、以及萬一停止維運的備援計畫（此次未深入其 GitHub README 確認資料抓取管線細節）。
5. **委員會代號對照表未取得**：`/meets` 用 `委員會代號` 過濾，但代號與委員會中文名稱的對照表本次未查到，需另外向 API 文件確認。
6. **姓名比對與遞補委員**：務必以 `歷屆立法委員編號` 作為唯一鍵，不可僅用姓名字串比對（同名/異體字/羅馬拼音混排風險已在樣本中出現）。
7. **公督盟評鑑資料**：僅確認網站存在評鑑選單，未實際打開內容頁確認資料型態（HTML/PDF）與是否可合法轉載，此為未完成項，需要後續針對 `ccw.org.tw/assess` 做更深入驗證。
8. **沃草國會無雙現狀未明**：原網域 DNS 失敗，需先找到現行網址才能評估，不應視為現成可用來源。
