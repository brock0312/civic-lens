## 1. 司法院裁判書

### 1.1 法學資料檢索系統（人工網頁查詢）
- URL：`https://judgment.judicial.gov.tw/FJUD/default.aspx`
- 實測：`curl -A "Mozilla/5.0"` → HTTP 200，取得含「查詢」字樣之頁面，但整頁為 ASP.NET + JS 動態渲染，未能用純 curl 取得判決書列表或去識別化說明文字。
- 已知（知識庫推論，未逐條核對條文出處，本次未查證原文，建議下輪任務補查）：
  - 民事/刑事一般判決書上網公開時，**當事人姓名原則不遮蔽**，但下列類型依法/依實務強制去識別化或不公開：少年事件（少年事件處理法）、性侵害案件被害人（性侵害犯罪防治法）、家事事件（家事事件法）、涉及國家機密或未成年子女最佳利益之部分。
  - 「是否為確定判決」網頁上通常僅顯示終審級別與是否上訴，**沒有官方欄位直接標示「已確定」**，需自行比對是否有上訴審或是否逾上訴期，這是一個重要缺口。
- 坑：無官方公開 REST API 供程式化查詢判決全文；市面工具多為爬蟲。若做爬蟲需注意查詢頁有驗證碼/查詢頻率限制（本次未實測觸發門檻）。

### 1.2 司法院資料開放平台 — **第二輪已找到真實裁判書批次資料集**
- URL：`https://opendata.judicial.gov.tw/`
- 第二輪方法：Playwright 開真實瀏覽器攔截首頁 XHR，找到真正的資料集查詢 API：`GET https://opendata.judicial.gov.tw/api/Datasets?keyword=裁判書&page=1`
- **已實測可用**：回 200＋真實 JSON，該關鍵字命中 **369 筆資料集**，包含：
  - 逐月裁判書全文批次檔，命名如「199601裁判書」「202607裁判書--(20260916Update)」，從1996年1月至今每月一包，格式多為 RAR（近期也看到會更新既有月份，檔名帶 Update 字樣代表歷史資料仍可能被覆寫/更正）。
  - 欄位說明（來自 `mainColumnDesc`，已實測讀到）：`ID(案號)、JYEAR(年度)、JCASE(字別)、JNO(號碼)、JDATE(裁判日期)、JTITLE(案由)、JFULL(全文)、JPDF(裁判書PDF檔下載連結)` —— **JFULL 全文欄位存在，代表裁判書全文（含姓名，除非依法遮蔽）可批次取得，非僅後設資料**。
  - 另有一筆特別資料集「Delete-Infor裁判書」（CSV格式）——推測為「已下架/刪除裁判書清單」，對判斷「該筆判決是否仍然有效公開」可能有參考價值，但本次未下載內容確認欄位定義。
- **已知坑（本次實測到的平台真實問題）**：資料集清單 API（`/api/Datasets`）運作正常，但**資料集詳情 API（`/api/Datasets/{id}`）對本次抽測的多個裁判書資料集 ID（58127、58128、57761等）全部回傳 HTTP 500「Entity "GetDatasetQuery" (id) was not found」**——包括直接用瀏覽器正常導覽到該資料集詳情頁也會觸發同樣 500，證實這是平台本身當下（2026-09-28）的錯誤/不穩定，並非我方存取方式錯誤（同一 API 對其他資料集，如 id=37182「裁判書用語辭典資料庫」，可正常回200）。因此，**本次仍未能實測到裁判書批次檔的實際下載連結、確切更新頻率與授權條款版本**（推測與平台其他資料集一致為「政府資料開放授權條款－第1版」，已於 id=37182 確認此授權文字，但未在裁判書資料集本身確認）。
- **確定判決／去識別化規則**：本次仍未查到官方原文說明「JFULL全文中當事人姓名是否遮蔽」及「如何標示是否為確定判決」，此為本輪最大未解缺口，需要能正常打開資料集詳情頁（或下載一包 RAR 實際檢視內容）才能確認，建議待平台 500 錯誤修復後或用其他資料集ID重試。

### 1.3 姓名比對可行性與同名誤判
- 因裁判書多數不遮蔽姓名，理論上可用姓名比對，但台灣常見姓名（如「陳○○」「林○○」）同名同姓機率高，加上裁判書不附身分證字號，**無法唯一識別身分**，同名誤判風險高。
- 建議護欄：任何前科呈現都必須附「原始判決字號＋法院＋日期」連結供使用者自行核對，**絕不能只憑姓名比對就下結論**，且應在 UI 明示「同名不代表同一人」。

## 2. 經濟部商工登記公示資料 — **第二輪已找到並實測正確 API**

- URL：`https://data.gcis.nat.gov.tw/`（Swagger 規格：`https://data.gcis.nat.gov.tw/resources/swagger/swagger.json`，200 可直接下載，`basePath: /od/data/api`）
- 方法：第一輪純 curl 猜的 dataset UUID 全部無效；第二輪用 Playwright（帶真實 User-Agent，因為預設 headless UA 會被導向「系統忙碌中」的反爬蟲頁）打開首頁拿到 `/od/detail?oid=...` 連結，再讀取 detail 頁面文字說明，並下載 swagger.json 取得完整 16 組官方 API 清單與參數。
- **重要已知坑**：`data.gcis.nat.gov.tw` 對沒有標準瀏覽器 UA 的請求（含預設 headless Chromium）會回傳「系統忙碌中，請稍後再試一次」的假錯誤頁（並非真的忙碌），必須帶正常瀏覽器 User-Agent 才會放行。
- 授權：detail 頁面明確列出「授權方式：政府資料開放授權條款－第1版」「計費方式：免費」「編碼格式：UTF-8」，並要求使用者附「顯名聲明：提供機關／經濟部商業發展署」，否則視為未取得授權。
- 資料量與更新頻率（官方頁面文字，已實測讀到）：「公司登記基本資料」約 162 萬筆，更新頻率「不定時」。

## 3. 第三方公司資料整理

### 3.1 g0v company.g0v.ronny.tw — **已實測可用**
- 端點：`GET https://company.g0v.ronny.tw/api/search?q=<關鍵字，URL編碼>`
- 實測結果：HTTP 200，回傳 JSON，樣本（查「台積電」）：
  ```json
  {"data":[{"公司狀況":"核准設立","公司名稱":"台積電機有限公司","資本總額(元)":"2,000,000",
  "代表人姓名":"王志聰","公司所在地":"...","登記機關":"台中市政府",
  "核准設立日期":{...},"所營事業資料":[...]}]}
  ```
  （注意：搜尋「台積電」關鍵字命中的第一筆是同名小公司「台積電機有限公司」，不是台灣積體電路製造股份有限公司——**代表關鍵字模糊比對容易誤命中同名/近似字號公司，反查時必須用統一編號而非公司名關鍵字做唯一識別**。）
- **第二輪已實測**：`GET /api/name/<人名>` 端點**確實存在**（回200，結構為 `{"data":[],"found":0}`），但對兩個測試姓名（「魏哲家」「郭台銘」）皆回傳 `found:0`——推測此端點索引的是「登記負責人」或另一種身分而非全體董監事，或索引未涵蓋這兩人；**尚未成功用任何真實姓名觸發非零結果**，故「以人名反查任職公司」在 g0v 這個端點上**未證實可行**，需再用更多樣本測試（例如中小企業負責人）才能下結論。
- 另實測 `company-graph.g0v.ronny.tw`（README 中列出的「台灣公司關係圖」子專案）的 `/index/json?id=<姓名>` 端點：回200，但對「魏哲家」「郭台銘」皆回傳空邊（無關聯節點），且其節點欄位含 `funder`（金主/捐助人），研判此圖是以**政治獻金／出資關係**為主軸的圖譜，並非泛用的公司董監事關係圖，用途與本專案「查董監事任職」的需求不完全對應。
- 已讀取 GitHub `ronnywang/twcompany` 專案 README（`raw.githubusercontent.com`, 200）：確認授權為 **BSD License**（程式碼），資料來源為「經濟部商業司 公司資料異動清冊」（每月初更新）＋「財政部全國營業稅籍登記資料集」（每日更新），可下載完整打包檔（`ronnywang-twcompany.s3-website-ap-northeast-1.amazonaws.com`）。
- 已知坑：資料為政府開放資料的「快照」，非即時，存在更新延遲（依README每月/每日更新頻率）；且如上例，用中文簡稱模糊搜尋容易誤配對到名稱相似但完全不同的公司。

### 3.2 台灣公司網等其他第三方
- 未實測（本次時間內未逐一打）。已知：多數台灣公司網站是廣告導向的商業服務，資料來源同樣是 GCIS 開放資料，**授權條款通常未明確公開，不建議直接爬取轉引**，若要用應以 g0v 或官方 GCIS 為主，第三方商業站僅作交叉核對用途。

## 4. 監察院陽光法案：財產申報公報 — **第二輪已找到並實測真正的查詢系統**

- 首頁 `https://sunshine.cy.gov.tw/`：實測 200，是「陽光法令主題網」入口網站（新聞/法規宣導為主），**本身不是查詢系統**。從導覽選單「公告園地 → 財產申報公告資料」的連結挖出真正系統：`https://priso.cy.gov.tw/layout/baselist`。
- **已實測可用**：`priso.cy.gov.tw`（Angular SPA，title「PrisOut(正式機)」）提供「財產申報資料查詢」表單，可選欄位：專刊期別、刊登類別、服務機關、職稱、**姓名**、不限欄位。實測以「柯文哲」查姓名，成功回傳 8 筆真實索引資料，樣本：
  ```
  柯文哲 | 207(廉政專刊) | 臺北市政府/市長 | 01一般申報 | 民國112年04月18日 | P132-136
  ```

## 6. 法律風險

### 6.1 個人資料保護法
- 第 2 條：姓名、身分證字號、財務情況、犯罪前科等均屬本法所稱「個人資料」。
- 第 6 條：有關犯罪前科之資料屬「特種個資」，原則禁止蒐集處理利用，但**已合法公開者**或法律明文規定得以蒐集之情形除外——本專案定位為「僅使用選舉公報依法揭露內容＋司法院已確定判決之公開判決書」，屬於「當事人自行公開」或「法律明文應公開」的例外態樣，legal basis 需在產品文件中明確標註引用第 6 條第 1 項第幾款。
- 第 19 條（非公務機關蒐集或處理個資之特定目的）、第 20 條（特定目的外之利用）：從政府公開資料／裁判書「再蒐集並整理成新資料庫」，若原始公開目的是「司法透明／選舉監督」，本專案之「選民監督」用途與原始公開目的具高度關聯性，屬同法第20條第1項但書「為增進公共利益」或「特定目的外之利用經當事人同意」等除外情形較站得住腳，但**仍需在產品內明確揭示資料來源、蒐集目的、僅限於候選人/公職人員本人及依法應揭露之配偶與未成年子女範圍**，不得擴及一般民眾或其他親屬。
- （以上條文引用為一般法律知識，本次未逐條核對全國法規資料庫最新版條號與文字，正式上線前應請具資格之法律專業複核最新條文。）

### 6.2 政府資料開放授權
- 各平台若標示「政府資料開放授權條款」，通常允許姓名標示後之非商業/商業再利用，但**各平台版本與限制不一**（本次未逐一核對 gcis/judicial/cy.gov.tw 各自標示的授權版本號），使用前需個別核對每個資料來源頁面上的授權聲明文字，不可假設一致。

### 6.3 誹謗與同名誤判實務
- 民法第184條（侵權行為）、刑法第310條（誹謗罪）：若因同名誤植而公開指控特定人有前科或不當公司關聯，可能構成侵權或誹謗。
- 建議護欄（產品層級）：
  1. 前科呈現一律附「法院＋案號＋判決日期」原始出處連結，不做「僅憑姓名」的自動關聯推論。
  2. 公司關聯查詢一律以統一編號為唯一鍵，不得以姓名模糊比對後直接顯示「某某人是某公司負責人」，須顯示比對信心層級與提醒使用者自行核實。
  3. 財產申報僅呈現配偶／未成年子女姓名與依法應公告之資產類別，不做金額精確化或跨資料源臆測（例如不可反推存款餘額）。
  4. 所有頁面顯示「資料來源：xxx（連結）、擷取時間：xxx」，供使用者對原始公報/判決書做自行核對。
