**法源**
- 選罷法第 47 條（最新修正 115-07-01）規定的公報內容**不含前科**，犯罪紀錄只出現在第 26 條的登記資格限制。G5 只能依靠司法院裁判書。
- 公職人員財產申報法（111-06-22 修正）第 2 條第 3 項規定，縣（市）級以上公職候選人**於申請登記時就要申報財產**；第 5 條第 2 項要求配偶、未成年子女的財產一併申報；第 6 條第 3 項要求受理機關於**審定候選人名單之日上網公告一年**。因此 2026 新人也有法定、公開的相關人資料。

## 3. 開源專案：自建或重用

| 專案 | 現況 | 決定 |
|---|---|---|
| `openfunltd/ly.govapi.tw-v2`（v2.ly.govapi.tw） | 活躍；資料 CC BY 4.0，程式 BSD-3 | **直接當作立委資料層**，不自己寫立院爬蟲 |
| 中選會 `db.cec.gov.tw/static/elections/data/...` JSON | 官方，已實測，只到 2022 | 用於歷屆候選人與得票。`cand_id` **每次參選都會重新編號**，不能當人物主鍵（見 §5） |
| GCIS 商工 API | 官方，已實測（curl 預設 UA 可用；headless 瀏覽器會被擋） | 直接使用，以統編查董監事、以公司名查統編 |
| `ronnywang/twgeojson`（程式 2013 年）、`taiwan-address-lookup`（2017 年） | 久未維護 | **不採用**：村里界太舊。V2 改用中選會開票 JSON 的村里層級資料，搭配內政部現行村里界（1150817 版） |
| `kiang/elections`（MIT，活躍） | 候選人資料平台 | **不當來源**（V1 已查）：repo 只有 2026 村里長；elections.olc.tw 有臺北名單，但資料授權與 birth 欄位出處都不明 |
| `g0v/councilor-voter-guide`、`g0v/twly-voter-guide` | 2018 年起停止維護、無 LICENSE、爬蟲目標已失效 | 只參考資料模型，不 fork、不用它的資料 |
| council2026.taiwangogo.tw | 活躍；台灣前進製作、時代力量代管；無資料授權聲明 | **完全不使用**。原因：有政黨背景，會損害中立性；授權也不明 |

結論：**立委部分靠現成 API，議會與政見部分自建**。需要自建的有：議會爬蟲（臺北市）、政見兌現資料集、身分對齊、G5/G6 的比對層。

## 4. 架構（預設提案，建置開始時再確認）

```
GitHub Actions cron（每日）
  └─ Python ETL（每個來源一支 script）→ SQLite 單檔（含 source_url、fetched_at）
       └─ 匯出靜態 JSON（依選區／人物切檔）→ 靜態前端（GitHub Pages 或 Cloudflare Pages）
```

- **不架後端伺服器**：沒有維運負擔，也不在執行時對外查詢，法律風險面較小。
- 每筆事實都存 `source_url` 與 `fetched_at`，前端一律顯示出處。
- 前端框架延到 Phase 1 開始時再選。

## 5. 身分對齊（整個專案成敗的關鍵）

- **自編 `person_id`**。各來源的 ID 都只是對照欄位，不當主鍵：
  - 中選會 `cand_id`：每次參選各有一個（例如柯文哲 2014 年是 64，2018 年是 81），只能識別「某一次參選」。
  - govapi `歷屆立法委員編號`：跨屆穩定，可以對應立委。
  - 臺北市議員：議會名錄沒有 ID。
- **比對依據**：姓名＋出生年月日。選舉公報有完整生日，中選會 JSON 只有出生年（`cand_birthyear`）。V1 已確認登記冊與名單公告都**不含生日**。臺北市範圍約百人，全部人工確認後寫進對照表。
- **公報上網前怎麼對齊**：只有「曾參選者」有舊紀錄要串接，這一組用 2022、2018 公報的生日人工確認；與舊公報同名的約 55 人，同名不代表同一人。新人在 2026 之前沒有任何紀錄可以串，公報前只用「2026 選舉＋選區＋姓名」識別，公報上網後再補生日。
- **不確定就不顯示**：比對結果只要不是唯一，一律不顯示。

## 6. 護欄（G5／G6 上線前必須全部到位）

1. **G5 前科**：只顯示同時符合以下條件的判決：①判決內文出現可佐證身分的資訊（例如職稱「臺北市議員」、選區，或與已知出生年月日一致）；②能確認是確定判決。每筆附判決字號與司法院原文連結，**不做摘要式定性**（只列罪名、字號、結果）。
2. **G6 公司關係**：**反過來比對**。先從財產申報中本人、配偶、未成年子女**自己申報**的股票與事業投資取得公司名稱，用 GCIS 換成統編，再查該公司的董監事。**不做「以人名搜尋全國董監事」**，因為同名誤判的風險太高。
   - **覆蓋限制，必須在介面上明示**：財產申報只涵蓋超過申報門檻的持股（財產申報法第 5 條第 1 項）。只擔任董監事或代表人、但沒有申報持股的職務，這個方法查不到。沒有結果時，介面顯示「申報資料中未見公司持股」，**不能顯示「無公司關係」**。
3. 提供「當事人補充說明」管道與更正流程。
4. 上線前，由 `security-executor` 審查個資法第 19、20 條（特定目的外利用）的依據與頁面免責聲明。
   - **黨徽使用**（Phase 1 就會顯示，要在 11/07 前審完）：圖檔取自內政部政黨資訊網，但內政部的資料開放宣告明文「不及於商標」，黨徽的著作權與商標權屬於各政黨。要確認本站的辨識用途是否屬於指示性使用或合理使用（見 [validation/party-emblems](validation/party-emblems.md)）。
5. 不評分、不排名、不使用政黨背景網站的資料。唯一例外是以「外部連結加揭露式聲明」提供 council2026.taiwangogo.tw，而且不轉載任何內容（2026-09-30 使用者決定，見 README）。
