## 2. 司法院裁判書系統（FJUD）

### 2.1 單筆原文與歷審

```
# 判決原文（id 是 FJUD 的主鍵，逗號分隔：法院代碼, 年度, 字別, 號, 裁判日期, 序號）
$ curl -sS -A 'civic-lens-etl/0.1' 'https://judgment.judicial.gov.tw/FJUD/data.aspx?ty=JD&id=TPHM%2C114%2C<字別>%2C<號>%2C<YYYYMMDD>%2C1'
  → 200，約 150–200 KB HTML；全文在頁面裡，不需要執行 JS
# 歷審清單（頁面 JS 用 GET 取得，jid 可以從原文頁面原樣抓出來）
$ curl -sS -A 'civic-lens-etl/0.1' 'https://judgment.judicial.gov.tw/controls/GetJudHistory.ashx?jid=<從頁面抓出的 jid>'
  → 200 {"count":2,"list":[{"desc":"臺灣臺北地方法院 … 判決(114.06.18)","href":"data.aspx?…","red":0}, …]}
# 全文檢索：GET default.aspx 取得 __VIEWSTATE → POST txtKW → GET qryresultlst.aspx?ty=JUDBOOK&q=<hash>
  → 200，每頁 20 筆，可用 & 組合關鍵字（例如「姓名&案由」）
```

**bot-defense 的實測結果**（F5 類型的防護，被擋時回 200，內容是 260 bytes 的「Request Rejected」）：

| User-Agent | 結果（各測 3 次以上） |
|---|---|
| `Mozilla/5.0`（光禿禿的） | ❌ 每次都被擋 |
| `civic-lens-etl/0.1`（誠實標示的 bot UA） | ✅ 每次都放行（原文、歷審、檢索頁都通） |
| 完整的 Chrome UA | ✅ 放行 |

**ETL 用 `civic-lens-etl/0.1` 就可以，不需要偽裝成瀏覽器。** 另外確認司法院「裁判書開放 API」`https://data.judicial.gov.tw/jdg/api/Auth` 存在：要註冊帳號，非服務時段回 `{"error":"目前非本 API 服務時間。"}`（20:29 實測）。這是長期量產比較正規的管道，但本次沒有申請帳號。

**歷審清單的語意**（頁面上的說明原文）：黑色圖示表示「案件目前繫屬法院或無該案號裁判書」，紅色表示「案件目前上訴到最高法院／最高行政法院審理中」。實測看到的條目類型：
- 有 `href`：該審級的判決或裁定。
- `href == ""`，desc 只有案號：還在審理中（例如「臺灣高等法院 115 年度上訴字第 N 號」）。
- desc 帶 `[撤回上訴]`：上訴已撤回。
- **舊案沒有資料**：2011、2019 年的兩件一審判決，`count` 都是 0，連案件本身都沒有列出。**`count == 0` 代表沒有資料，不代表沒有上訴。**

### 2.2 遮蔽規則

實測 5 件刑事判決（2011–2026 年，地院和高院都有）：
- 當事人欄只有「被告 姓名 ／ 選任辯護人 姓名」。過去判決書格式中「男 民國 xx 年 x 月 x 日生 身分證統一編號 … 住 …」這一整行，**在公開版本裡整行刪除**，不是遮成 ○。
- 內文的地址遮成 `臺北市○○區○○街00號5樓`；長串數字（發票、帳號）遮成 0。**行政區常常會保留**，例如「在臺北市內湖區住處」。
- 被告、證人、告訴人的姓名都會公開。是不是公職人員，處理方式都一樣。
- 依據：法院組織法第 83 條（公開裁判書時，除了自然人的姓名以外，可以不包含身分證字號等足以識別個人的資料）；司法院秘書長 101.10.29 秘台廳司一字第 1010030347 號函（不包含身分證字號、護照號碼、出生年月日、地址）。少年事件、性侵害等案件依專法另行遮蔽或不公開，本次沒有碰到。

### 2.3 怎麼判斷判決已經確定

刑事判決在上訴期間屆滿、上訴撤回或者不得上訴時確定。**FJUD 沒有「確定」欄位，司法院也沒有公開的確定查詢服務**：「案件進度查詢」只開放給被告、自訴人、告訴人等當事人，申請時要提供身分證字號（WebSearch 轉述司法院網站，見來源清單）；裁判確定證明書也只核發給當事人。

| 方法 | 怎麼做 | 可靠度 | 試做時看到的 |
|---|---|---|---|
| A. 文末寫「不得上訴」 | 抓判決最後 3,000 字 | **高**。刑訴第 376 條的案件，二審判決後就確定。例外是第 376 條第 1 項但書：一審無罪、二審改判有罪時，被告還可以上訴一次，所以要再核對主文和一審結果 | 2 筆 |
| B. 歷審清單出現 `[撤回上訴]` | `GetJudHistory` | **高**（法院系統自己標示的） | 1 筆 |
| C. 後續裁定稱它為「確定判決」 | 歷審清單裡的聲再、非常上訴、定應執行刑等裁定，或用全文檢索找引用這個案號的文書 | **高**（聲請再審的前提就是判決已經確定，裁定本文也直接寫了「第二審確定判決」） | 1 筆（與 A 重疊） |
| D. 最高法院判決駁回上訴，或自為判決 | 歷審清單 | 高（本次沒有碰到） | 0 |
| E. 歷審清單有尚未結案的上級審 | `href==""` 或 `red==1` | **高**，但是是反向訊號：**一定還沒確定** | 3 筆 |
| F. 共同被告的上級審判決沒有列這位被告 | 讀上級審的當事人欄 | 中（推論他沒有上訴，判決沒有寫明） | 1 筆 |
| G. 一審判決、找不到任何上訴紀錄 | 歷審清單的 `count==0` ＋ 全文檢索 | **判斷不了**。也可能是歷審清單沒有收錄舊案，或者上訴審判決沒有公開 | 3 筆 |
| H. 一審文末寫「如不服本判決應於…上訴」 | — | 只代表當時還可以上訴，**不代表後來有沒有確定** | 所有一審判決都有 |

**結論**：A、B、C、D 可以當作「已確定」的正面證據；E 可以用來排除；F 和 G **判斷不了，所以不顯示**。G 正好是一審就結束的輕罪最常見的情形（簡易判決、簡式審判），這是 A 方案最大的覆蓋缺口。如果使用者想放寬，可以考慮「判決日起滿 N 年＋兩種管道都查不到上訴」的推定規則，但這等於由本站推論判決已確定，和「只顯示已確定」的承諾有落差。**本報告不建議放寬。**

另外，已確定的判決還是可能因為再審、非常上訴而撤銷，或者被司法院從 FJUD 下架（開放平台有一份「Delete-Infor 裁判書」清單）。ETL 每次執行都要重新抓原文和歷審，失效就移除。

## 3. 身分佐證標準

### 3.1 判決裡有哪些可以用的資訊

| 資訊 | 判決裡有嗎 | 可以拿來比對的對象 |
|---|---|---|
| 姓名 | 有 | 必要但不夠。全文檢索單一姓名的命中數：試做的姓名分別是 93、42、32 件，混雜同名者、證人和告訴人 |
| 出生年月日、身分證字號、住址 | **沒有**（整行刪除） | — |
| 職稱或參選身分（「臺北市議會議員」「第 N 屆臺北市議員之擬參選人」「某選區立委候選人」） | **有時候有**（臺北 10 筆中有 5 筆） | CEC 歷屆候選人資料（姓名、選區、黨籍、`cand_birthyear`）、議會名錄、`identity.csv` |
| 屆次、任期、時間 | 有時候有 | CEC 的選舉日期、議會的屆次 |
| 行政區（「臺北市內湖區住處」） | 有時候有 | 本站沒有候選人的住址，**不能用** |
| 案情和公職的關聯（質詢、議會預算、選舉） | 有時候有 | 只能輔助，不能單獨成立 |
| 年齡、教育程度 | 量刑段落偶爾會寫「自述之智識程度」，不會寫具體數值 | 不能用 |

### 3.2 建議標準：「寧可不顯示，也不錯掛」

**一筆判決要全部符合以下條件才能顯示：**

1. **它是判決，而且是有罪判決**：主文判處刑罰（包含緩刑、免刑），不是起訴書、不是行政處分、不是無罪或不受理。案號、字別都以 FJUD 原文為準。
2. **確定關卡**：有第 2.3 節 A、B、C、D 其中一種正面證據，而且歷審清單沒有尚未結案的上級審（E）。
3. **身分關卡**：以下兩條路徑擇一，而且全程姓名都完全相同：
   - **路徑 1（判決內有身分錨點）**：判決內文寫出可以對到公開名冊的身分，例如「臺北市議會第 N 屆議員」或「某年某選區某黨候選人」；這個身分在該名冊上**只對到一個人**；而且這個名冊上的人，可以用**出生年月日（或至少出生年＋黨籍＋選區沿革）**連到本站的 person。
   - **路徑 2（同案的歷審判決有錨點）**：同一案件其他審級的判決有路徑 1 的錨點，可以沿用。**不同案件之間不能互相借用錨點。**
4. **只有姓名＋行政區＋案情相似，一律不顯示。**用新聞報導或 taiwangogo 的描述來補強身分，也一律不顯示。
5. **人工核可**：由人寫進對照表（例如 `data/convictions.csv`，欄位 `fjud_id, person_id, finality_basis, identity_basis, verified_by`），格式比照 `identity.csv`。ETL 只顯示表上有的判決，並且每次執行都重新驗證第 2 點。

### 3.3 和候選人資料怎麼比對

- **現任議員**：`identity.csv` 已經對齊；2022 公報的生日由 ETL 從公報取得（不寫進 dump），也可以用 CEC 2022 開票 JSON 的 `cand_birthyear` 輔助（已實測：試做的丙在兩屆 CEC 開票資料中的出生年一致）。
- **曾經參選的人**：判決的錨點 →（姓名＋選區＋黨籍＋選舉年）→ CEC 該次選舉的開票 JSON（有 `cand_birthyear`）→ 出生年 → 本站 person。**本站目前所有人的 `birth_year` 都是 NULL**，新人的 2026 資料要等 11/25 公報（出生年月日），或選後的開票 JSON（出生年），才能完成最後一段。
- **從來沒有參選過、判決也沒有錨點的人**：沒有任何公開的身分資料可以連結，**不顯示**。

## 6. 法律與倫理問題（交 security-executor 審查，PLAN §6 第 4 點）

1. **選擇偏差**：線索來自有政黨背景的網站，合作政黨在全國 26 位候選人中列名 0 人（第 1.4 節）。本站只查證它的線索的話，「誰被查」就繼承了它的選擇，就算每一筆判決都是真的。建議至少對所有候選人跑一次第 5 節的全文檢索，或者在頁面上說明「查證範圍以公開線索為起點，不代表其他候選人沒有判決」。
2. **用語不要寫「前科」**：刑法第 76 條規定，緩刑期滿而緩刑宣告沒有被撤銷的，刑之宣告失其效力。這類判決雖然已經確定，法律上已經不算有罪科刑紀錄。建議頁面標題用「確定有罪判決」，主文原文照錄（包括緩刑、易科罰金），不加任何定性。少年案件依法不公開，本來就查不到。
3. **錯掛是最大的風險**：民法第 184 條、刑法第 310 條。這就是第 3.2 節採用嚴格標準的理由。
4. **個資法第 6 條**：犯罪前科屬於特種個資，要確認「已合法公開」的但書，是否涵蓋 FJUD 判決的重新蒐集與利用，並寫明法律依據（交審查，本報告不下結論）。
5. **判決原文含第三人姓名**（共同被告、告訴人）：本站只連到司法院原文，不轉載內容、不擷取第三人，**data 欄位只放本人的罪名和刑度**。
6. **taiwangogo 的使用方式**：只把它的條目當作「要查哪個案號」的線索，內容不轉載、不進 repo。它的 `status` 有過時的情況（第 1.3 節），不能引用為確定狀態的依據。
7. **bot-defense**：誠實標示的 UA 就能通過，不需要繞過任何防護。長期量產建議申請司法院裁判書開放 API。

## 7. 建議的 ETL 資料形狀

原提案是 `kind = conviction`、`data = {court, case_no, judgment_date, offense, result, final, title}`、`source_url` 是司法院原文網址。建議調整如下：

```json
{
  "court": "臺灣高等法院",
  "case_no": "114年度上易字第N號",
  "judgment_date": "2026-04-15",
  "title": "臺灣高等法院 114 年度上易字第 N 號刑事判決",
  "offense": "<主文罪名原文>",
  "result": "<主文刑度原文，含緩刑／易科罰金>",
  "finality_basis": "no_appeal_allowed | appeal_withdrawn | later_ruling_states_final | supreme_court",
  "finality_evidence_url": "<證明已確定的那份文書，例如聲請再審裁定；與 source_url 相同時可省略>",
  "identity_basis": "title_in_judgment",
  "related": [{"court": "臺灣臺北地方法院", "case_no": "…", "judgment_date": "…", "url": "…"}]
}
```

- **`final` 改成 `finality_basis`**：沒確定的判決根本不寫進資料，所以布林值永遠是 true，沒有資訊量；改成記錄判斷依據，方便稽核和重新驗證。
- **加 `related`（歷審）**：二審只就刑度上訴時，罪名在一審判決、刑度在二審判決（例如試做的甲），只連一份判決會讓人看不懂。
- **`source_url`** 指向確立最後結果的判決（通常是最後一審），id 一律 percent-encode；`fact_key = conviction:<FJUD id>`；`date` 欄位放 `judgment_date`。
- **身分核可放在對照表**（`data/convictions.csv`，見第 3.2 節第 5 點），不放進 data。ETL 只讀這張表，並且每次執行都重新抓原文和歷審：原文失效、出現撤銷或再審改判，就不輸出這筆。
